# 南极UEFI标准与GFS文件系统

## 一、UEFI的基本概念

UEFI（Unified Extensible Firmware Interface，统一可扩展固件接口）是取代传统BIOS的固件接口标准，在操作系统和硬件固件之间架桥。

**传统BIOS的问题：** BIOS诞生于1981年IBM PC时代，16位实模式，1MB寻址空间，启动流程硬编码，每一步都是死的且极慢。

**UEFI的核心能力：**

- 直接运行在32位或64位保护模式下，可访问全部内存
- 用GPT分区替代MBR（支持无限分区、超大磁盘）
- 引导管理器：读取EFI系统分区中的.efi可执行文件启动操作系统
- Secure Boot：只允许加载经过签名验证的.efi文件（南极物理不可能）
- UEFI Shell：完整的微型操作系统，可运行命令行程序、诊断工具
- 通过ACPI表告诉操作系统"CPU核心数、内存分布、电源管理"
- 通过SMBIOS表告诉操作系统"主板型号、固件版本"

**地球上UEFI的标准化层级：**
1. UEFI规范本身（UEFI Forum发布）
2. PI（Platform Initialization）规范——PEI→DXE→BDS→启动操作系统
3. 芯片组厂商参考实现（Intel/AMD垄断）
4. 主板厂在参考实现上修改

这个标准化层级之所以成立，是因为UEFI Forum有权威、芯片组被垄断。

## 二、南极的UEFI标准：六种方案共存

南极没有统一的UEFI标准。没有UEFI Forum。FI芯片没有垄断性芯片组参考实现——芯片设计集团有很多家，每家都可能有自己的初始化方式。每家主板厂编写自己的UEFI固件时，不是"在参考实现上修改"，是"从零设计启动流程"。

所有曾经试图统一UEFI标准的尝试都失败了——六种启动方案已经各自在无数设备上跑了十几年，ROM固化派说"这是最正常的方案"，START分区派说"这是南极原创精神"，OEM预配派说"数据中心不需要启动菜单"。谁都说服不了谁。NARITC甚至懒得正式提议——任何UEFI统一提案连2/3的初步讨论都熬不过去。

最终：GlacierOS自己扛。内核代码中有相当一部分量级的UEFI兼容驱动。GlacierOneOS中UEFI启动兼容驱动估算占内核的25%-35%；GlacierTwoOS代码量暴增后，兼容层的绝对行数进一步膨胀。

### 方案一：ROM固化UEFI（地球风格）

主板上焊着一块SPI闪存，UEFI固件固化在里面。通电 → 主板初始化 → 从ROM加载UEFI → UEFI扫描所有磁盘找NSTART分区 → 加载bootloader。

这是最接近标准PC的方案。主要由s8s的标准FI服务器采用——s8s的客户不需要定制启动流程，只想要一台插电就能装GlacierOS的标准服务器。ROM固化UEFI的好处是简单：换硬盘不影响UEFI，主板自带的固件永远可用。坏处是升级UEFI需要刷ROM，刷坏了主板变砖。s8s的设计足够保守，ROM里的UEFI固件十年不更新也没事。

### 方案二：UEFI存于独立UEFI芯片（双芯片方案）

主板上集成两个独立芯片——UEFI芯片（小容量，只存UEFI固件，低功耗FI嵌入版处理器）和FI主芯片（CPU）。通电后UEFI芯片先上电，初始化完成后通过内部总线唤醒FI主芯片，把UEFI固件的执行结果传给主芯片。

这个方案的特点是UEFI芯片和主芯片物理隔离，主芯片上的任何代码都碰不到UEFI代码。星云的部分CLX开发主板采用此方案——CLX的控制总线需要独立于CPU的初始化逻辑，UEFI放在独立芯片上可配合编程模式/运算模式的切换。

维护成本高：UEFI芯片有自己的小操作系统，需要单独的驱动和固件更新工具链。GlacierOS适配它时，必须在内核启动早期识别"UEFI芯片型号→UEFI版本→支持的UEFI API版本"——若任何一项不匹配，启动失败。

### 方案三：UEFI存于硬盘START分区

UEFI固件存放在硬盘第一个分区（START分区）。通电 → 主板做最小初始化 → 去磁盘读取START分区 → 加载UEFI → UEFI再去NSTART分区加载bootloader。

主板必须内置一个极其简约的"UEFI加载器"——不是完整的UEFI，只是一段代码知道怎么从磁盘START分区读取第一个扇区。这段代码小到可以烧在CPU内部的微码ROM里，永远不需要更新，也不需要独立芯片。

这个方案的问题：换硬盘后连UEFI都没有，根本无法启动。

### 方案四：UEFI和bootloader合并存储于NSTART分区（一体化方案）

完全没有单独的UEFI阶段。START分区和NSTART分区合并为同一个分区。通电 → 主板做最小初始化 → 直接加载分区里的bootloader。bootloader内部自带所有硬件初始化逻辑——它既是bootloader又是UEFI。GlacierOS内核启动时不需要查UEFI API——因为根本没有UEFI。bootloader直接通过FI芯片的HAL层初始化硬件，把内核加载到内存，跳过去。

这个方案在民间极客中极受欢迎——少一个阶段、少一堆标准、少一堆兼容性麻烦。一台电脑就是一块主板+一个芯片+一块硬盘+一个分区。代价是：只能启动一个内核——因为bootloader是硬编码给特定OS的。想换别的小众OS？需要重新改写整个bootloader。

### 方案五：主板固件自动启动内核（OEM预配方案）

主板的固件芯片里直接烧了一个完整的bootloader——不是UEFI，是直接知道内核在哪的bootloader。出厂预装了GlacierOS的服务器，主板固件芯片里烧的bootloader指向默认安装路径。通电 → 初始化 → 直接加载内核，全程无UEFI、无用户可选启动菜单。

这是蓝天云和星云数据中心服务器最爱的方案——几十万台服务器不需要启动菜单。固件里写的路径不指向具体文件名，而是指向一个符号链接——更新由运维系统负责。缺点是如果符号链接出问题，全数据中心几十万台服务器同时启动不了。

## 三、ext4：僵尸文件协议

ext4是Linux的老牌文件系统，人类的遗产。极少数革命前时代遗留的老Linux设备存到现在，硬盘上还带着ext4。在南极它已经是彻头彻尾的僵尸——没人用它存新数据，没人维护它的驱动。

---

## 四、START分区与NSTART分区

START分区：存放UEFI程序的磁盘分区。机器通电，主板先通电，做最小初始化，去磁盘的START分区找主板的UEFI程序，随后UEFI程序启动，根据要求读取并启动NSTART分区的bootloader。

南极的启动流程跟地球PC完全反着来——地球上UEFI固化在主板SPI闪存里，换硬盘不影响UEFI。南极的UEFI当文件存硬盘上，换硬盘连UEFI都得重配。

这只是众多启动方案中的一种。其他主板厂商可能有自己的独有方案。
